Librery: Vision & Core Architecture Specification1. Executive SummaryLibrery is a next-generation, open-source Library Management System (LMS) designed to replace legacy, bloated platforms. It delivers enterprise-grade data integrity within an ultra-lightweight, zero-administration single binary, optimized specifically for edge deployments and constrained networks (e.g., rural district libraries).2. Architectural Paradigm: FCISLibrery operates on a strict Functional Core, Imperative/Reactive Shell (FCIS) pattern.The Functional Core (Pure Rust): Pure functions, zero side effects. It contains the exact mathematical rules of the library.The Imperative Shell (Rust / Axum): Handles all messy, real-world operations (database, network, CRDT syncing).3. Network Transport: HTTP/3 (QUIC) with HTTP/1.1 & HTTP/2 FallbacksTo support mobile patrons and offline-syncing staff apps on unreliable cellular networks, Librery natively serves HTTP/3 over QUIC.The Primary Engine (quinn): The Axum backend utilizes quinn to eliminate TCP head-of-line blocking, allowing Automerge patches and search queries to flow over multiplexed UDP streams.The Graceful Fallback (hyper): Because HTTP/3 requires client discovery, the Axum server concurrently binds to TCP using hyper to serve HTTP/1.1 and HTTP/2.The Protocol Upgrade: The backend injects the Alt-Svc: h3="... header into all HTTP/1.x/2 responses. This instructs modern browsers and clients to seamlessly upgrade subsequent requests to the UDP-based QUIC protocol, ensuring universal compatibility across both legacy hardware and modern mobile devices.4. Concurrency & Offline SyncCirculation (Ledger): To prevent race conditions, Axum routes push commands into a Tokio MPSC Actor Channel. A background task processes the queue chronologically, ensuring lock-free database writes.Metadata (CRDTs): Offline staff edit bibliographic CRDT documents locally; when the connection restores, the Axum shell resolves the binary patches seamlessly.5. CQRS & Read ModelsWrite Side: The SQLx event ledger acts as the absolute source of truth.Read Side: The background actor projects ledger events directly into an embedded Tantivy full-text search index for instant, fuzzy-matched OPAC queries without touching the transactional database.
